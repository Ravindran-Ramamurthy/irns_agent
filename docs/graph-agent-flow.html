How a decision moves through irns-agent

Three fire-and-forget triggers — a new risk event, a new incoming event, or a previous action's review time coming due — all funnel into one shared decision, which ends in exactly one of two outcomes: record the next action, or close the risk event. No node here ever pauses; every run finishes in a single pass.

record_action

Always an insert, never a mutation of the prior action — even a "nothing to do yet, check back at reviewAt" outcome is its own row with actionType = NULL. Status is always PENDING; most rows stay that way permanently, and that's fine. Also stamps the risk event's review_at.

POST /tenant/irns/action-event, + reviewAt field
close_risk_event

Reached only when the decision has neither an action nor a future review point. Sets the terminal status and clears review_at so the risk event drops out of the poll entirely.

PUT /tenant/irns/risk-event
Any step can end the run early. _after_load_domain routes straight to END if the domain isn't ingested; _after_decide does the same if the LLM call fails or its reply doesn't parse — same END the happy path uses, same as chat_agent/ivr_agent's own graphs. Nothing here needs a separate error terminal.
No pause, no polling loop inside the agent. Unlike ivr_agent's clarify node, nothing in this graph ever calls interrupt() — every run is triggered fire-and-forget and runs to completion in one pass. In particular, the agent itself never scans for due reviews — it only ever answers /actionevent when something else calls it with a risk event id. What that something is — a periodic job, a scheduler, whatever ends up calling this endpoint once review_at comes due — is a separate, not-yet-built piece outside this graph.
Closing is inferred, not a separate field. The decision schema has no explicit "can this close?" boolean — _after_decide reads it off what's present: actionType or reviewAt set → record_action; both absent → close_risk_event. One schema answers all three of the original questions (next action + its review time / can it close, else when to recheck / close if neither) by what the model chooses to fill in.
